# Step-by-Step Guide: Build a Claude Code Memory Harness for Any Project

This guide walks you through building a persistent memory system for Claude Code — so every new session starts with full context instead of zero. Adaptable to any project, any vault structure.

---

## Prerequisites

Before you begin, ensure you have:

- **macOS or Linux** (QMD runs locally)
- **Obsidian** installed (or any markdown-based knowledge base)
- **Claude Code** CLI installed and working
- **Bun** runtime (for installing QMD)
- **Homebrew** (macOS — for SQLite dependency)

---

## Phase 1: Set Up Your Knowledge Base

### Step 1.1 — Create (or Organize) Your Obsidian Vault

Structure your vault so each major content type lives in its own folder. This matters because each folder becomes a separate QMD "collection" with independent search.

```
your-vault/
├── notes/            # Project notes, research, architecture decisions
├── daily/            # Daily journal / standup entries
├── sessions/         # (Will be auto-populated with Claude Code sessions)
├── transcripts/      # Meeting notes, voice memos
└── skills/           # Claude Code skills you create
```

If you already have a vault, you don't need to restructure everything — just ensure your session export folder exists:

```bash
mkdir -p ~/your-vault/sessions
```

### Step 1.2 — Establish a Naming Convention

Consistent naming helps QMD rank results better:

```
notes/        → descriptive-name.md        (e.g., auth-system-design.md)
daily/        → YYYY-MM-DD.md              (e.g., 2026-03-04.md)
sessions/     → session-YYYY-MM-DD-HH-MM.md (auto-generated by hook)
transcripts/  → meeting-TOPIC-DATE.md
```

## Phase 2: Install & Configure QMD

### Step 2.1 — Install Dependencies

```bash
# macOS: Install Homebrew SQLite (required)
brew install sqlite

# Install Bun (if not already present)
curl -fsSL https://bun.sh/install | bash

# Install QMD globally
bun install -g https://github.com/tobi/qmd
```

### Step 2.2 — Register Your Collections

Each vault folder becomes a named collection. Register them one at a time:

```bash
# Register each folder as a QMD collection
qmd collection add ~/your-vault/notes       --name notes
qmd collection add ~/your-vault/daily       --name daily
qmd collection add ~/your-vault/sessions    --name sessions
qmd collection add ~/your-vault/transcripts --name transcripts

# Verify your collections
qmd collection list
```

### Step 2.3 — Generate Embeddings

This creates the vector index for semantic search. Run it once, then re-run whenever you want to update:

```bash
# Generate embeddings for all collections
qmd embed
```

This step takes a minute or two depending on vault size. It only processes new/changed files on subsequent runs.

### Step 2.4 — Test Your Search

Verify everything works:

```bash
# BM25 keyword search
qmd search "your project topic" -c notes -n 5

# Semantic search (requires embeddings)
qmd vsearch "what was that idea about improving performance" -c notes -n 5

# Hybrid search (best results)
qmd query "authentication architecture decisions"
```

If results come back ranked and relevant, you're ready for the next phase.

## Phase 3: Build the Session Sync Pipeline

This is the automation that makes sessions persist across conversations.

### Step 3.1 — Understand Where Claude Code Stores Sessions

Claude Code saves every conversation as JSONL files on your local machine:

```bash
# Default location (check yours)
ls ~/.claude/sessions/
```

Each file contains raw conversation data: tool uses, system prompts, assistant responses, user messages. The goal is to parse out the useful signal and save it as clean markdown.

### Step 3.2 — Create a Session Export Script

Create a script that converts JSONL sessions to searchable markdown. Save this as `sync-claude-sessions.sh` (or build it as a Claude Code skill):

```bash
#!/bin/bash
# sync-claude-sessions.sh
# Converts Claude Code JSONL sessions to clean markdown in your vault

SESSIONS_DIR="$HOME/.claude/sessions"
VAULT_SESSIONS="$HOME/your-vault/sessions"
PROCESSED_LOG="$VAULT_SESSIONS/.processed"

# Create processed log if it doesn't exist
touch "$PROCESSED_LOG"

for session_file in "$SESSIONS_DIR"/*.jsonl; do
    filename=$(basename "$session_file")

    # Skip already processed
    if grep -q "$filename" "$PROCESSED_LOG" 2>/dev/null; then
        continue
    fi

    # Extract date from filename or file modification time
    date_str=$(date -r "$session_file" "+%Y-%m-%d-%H-%M")
    output_file="$VAULT_SESSIONS/session-${date_str}.md"

    # Parse JSONL: extract user messages and assistant responses
    # Strip tool_use blocks, system prompts, and metadata
    python3 -c "
import json, sys

messages = []
with open('$session_file', 'r') as f:
    for line in f:
        try:
            msg = json.loads(line.strip())
            role = msg.get('role', '')
            content = msg.get('content', '')
            if role in ('user', 'assistant') and isinstance(content, str) and content.strip():
                messages.append(f'## {role.title()}\n\n{content.strip()}\n')
        except (json.JSONDecodeError, AttributeError):
            continue

if messages:
    print('\n---\n'.join(messages))
" > "$output_file" 2>/dev/null

    # Log as processed
    echo "$filename" >> "$PROCESSED_LOG"
done

# Re-index QMD
qmd embed
```

```bash
chmod +x sync-claude-sessions.sh
```

### Step 3.3 — Set Up Auto-Sync via Claude Code Hooks

Claude Code supports hooks that run on session events. Configure a hook to auto-export on session close:

Create or edit `~/.claude/hooks.json`:

```json
{
  "on_session_end": [
    {
      "command": "/path/to/sync-claude-sessions.sh",
      "description": "Export session to Obsidian and re-index QMD"
    }
  ]
}
```

Alternatively, if you're using the `/sync-claude-sessions` skill approach, place the skill in your `.claude/skills/` folder so Claude Code can invoke it directly.

## Phase 4: Create the /recall Skill

### Step 4.1 — Create the Skill Directory

```bash
mkdir -p ~/.claude/skills/recall
```

### Step 4.2 — Write the SKILL.md

The SKILL.md file tells Claude Code what the skill does and how to use it. Create `~/.claude/skills/recall/SKILL.md`:

```markdown
# /recall — Load Context Before You Start

## Purpose
Load relevant context from your knowledge base before starting work.
Instead of explaining what you were doing, tell Claude to recall.

## Modes

### Temporal — What happened recently?
Usage: `/recall yesterday` or `/recall last week`

Search session history by date. Reconstructs a timeline of sessions
with message counts, topics covered, and what was accomplished.

Implementation:
- Run: `qmd search "YYYY-MM-DD" -c sessions -n 20`
  (substitute the target date or date range)
- Summarize: timeline, session count, key decisions, open items

### Topic — Find everything about X
Usage: `/recall topic <query>`

BM25 search across ALL collections simultaneously.

Implementation:
- Run in parallel:
  - `qmd search "<query>" -c sessions -n 5`
  - `qmd search "<query>" -c notes -n 5`
  - `qmd search "<query>" -c daily -n 3`
  - `qmd search "<query>" -c transcripts -n 3`
- Synthesize results into a unified context summary
- Include file paths so the user can open them directly

### Graph — Visualize session relationships
Usage: `/recall graph last week`

Generate an interactive HTML visualization showing:
- Sessions as nodes (colored by recency)
- Files as connected nodes (clustered by type)
- Connections = which files each session touched

Implementation:
- Query recent sessions from QMD
- Parse file paths from session content
- Generate an HTML file with D3.js or similar visualization
- Open in browser
```

### Step 4.3 — Test the Skill

Open a new Claude Code session and try:

```
/recall topic "your recent project"
```

Claude Code should read the SKILL.md, understand the interface, run the QMD commands, and load your context automatically.

## Phase 5: Optimize for Your Project

### Step 5.1 — Tune Your Collection Strategy

For a **software project**, consider these collections:

```bash
qmd collection add ~/project/docs          --name project-docs
qmd collection add ~/project/.claude/notes  --name claude-notes
qmd collection add ~/your-vault/sessions   --name sessions
```

For a **research project**:

```bash
qmd collection add ~/vault/papers      --name papers
qmd collection add ~/vault/experiments --name experiments
qmd collection add ~/vault/sessions    --name sessions
```

For a **content creation** workflow:

```bash
qmd collection add ~/vault/drafts      --name drafts
qmd collection add ~/vault/research    --name research
qmd collection add ~/vault/published   --name published
qmd collection add ~/vault/sessions    --name sessions
```

### Step 5.2 — Choose Your Default Search Mode

**Start with BM25** (`qmd search`). It handles 80% of searches — fast and works great for structured notes with consistent terminology.

**Add semantic search** (`qmd vsearch`) for unstructured content: transcripts, braindumps, journal entries — places where you'd never search for the exact right keywords.

**Use hybrid** (`qmd query`) when you need the absolute best ranking and don't mind a slight delay.

### Step 5.3 — Set Up Cross-Device Sync (Optional)

If you work across multiple machines:

```
┌─────────────┐     Obsidian Sync     ┌──────────────┐
│  Laptop     │◄────────────────────▶ │  Desktop     │
│  Claude Code│    (or Git / iCloud)  │  OpenClaw    │
│  QMD local  │                       │  QMD local   │
└─────────────┘                       └──────────────┘
```

Each machine needs its own QMD install, but they share the same vault via Obsidian Sync, Git, or any folder-sync tool. After sync, run `qmd embed` locally to update the index.

## Phase 6: Verify & Maintain

### Step 6.1 — Verify the Full Pipeline

Run through this checklist:

```
[ ] qmd collection list         → Shows all your collections
[ ] qmd search "test" -c notes  → Returns ranked results
[ ] qmd vsearch "test" -c notes → Returns semantic results
[ ] /recall topic "any query"   → Claude loads context from QMD
[ ] Close a session              → Hook fires, session exported
[ ] Open new session             → /recall finds the previous session
```

### Step 6.2 — Ongoing Maintenance

**Daily**: Nothing. Hooks keep the index fresh automatically.

**Weekly**: Run `qmd embed` if you've added a lot of new notes outside of Claude Code sessions (manual vault edits, imported transcripts, etc.).

**Monthly**: Review your collection structure. As projects grow, you may want to split large collections or add new ones.

### Step 6.3 — Monitor Token Savings

The shift from grep to QMD typically reduces token usage by 90-96% for search operations. Track this by comparing:

- **Before**: Claude grepping through 300+ files → ~15,000 tokens per search
- **After**: QMD returning 5 ranked results → ~500 tokens per search

## Troubleshooting

**QMD returns no results** → Run `qmd embed` to rebuild the index. Check that `qmd collection list` shows your collections.

**Semantic search returns nothing** → Embeddings may not be generated. Run `qmd embed` and wait for completion.

**Hook doesn't fire on session close** → Verify `~/.claude/hooks.json` syntax. Test the script manually first.

**Results are stale** → The hook may not be running `qmd embed` after export. Add it as the final step in your sync script.

**Claude doesn't understand /recall** → Ensure SKILL.md is in the correct path (`~/.claude/skills/recall/SKILL.md`) and restart Claude Code.
